# ADR-0015: Implement a minimal PDF reader and an incremental-update writer

- **Status:** Accepted
- **Date:** 2026-10-23

## Context

PAdES signing appends an incremental update to the PDF document (ISO 32000-1, clause 7.5.6) containing a signature dictionary whose `ByteRange` covers the whole file except the signature value, and, at B-LT, a document security store holding validation data (ETSI EN 319 142-1). Verification must detect changes made after signing, including the shadow and incremental-save attacks published against PDF signatures since 2019.

Signing needs exact control over every byte written and must never rewrite earlier revisions. Verification needs a parser that is strict about structure but tolerant of the irregularities common in real documents, and that is safe on hostile input. General-purpose Rust PDF libraries, such as `lopdf`, load the whole document into an object model and write it back as a whole, which does not preserve earlier revisions byte for byte.

## Decision

A new crate, `sigillum-pdf`, provides:

- a minimal reader for the structures signatures need: header, cross-reference tables and streams, trailers, the revision chain, indirect objects on demand, the document catalogue, AcroForm fields and signature dictionaries;
- an incremental-update writer that only appends, computes the `ByteRange`, reserves and fills the signature contents, and writes the document security store;
- a revision analysis used by verification to report what changed after each signature.

Rendering, text extraction and content-stream interpretation are out of scope ([scope.md](../../project/scope.md)). `lopdf` may be used in tests as an independent second parser to cross-check the reader, but not in library code.

## Alternatives considered

| Option | Advantages | Disadvantages |
| --- | --- | --- |
| `lopdf` for reading and writing | Ready-made | Rewrites documents; no revision model; broad attack surface |
| `lopdf` for reading, own writer | Less code | Two models of the same document; parser not designed for hostile input |
| Own minimal reader and incremental writer | Exact byte control; small, fuzzable surface; revision model built in | More code to write and fuzz |

## Consequences

`sigillum-pdf` is a critical module: every parser entry point has a fuzz target, and the mutation-testing threshold applies. The corpus includes PDF files that exercise known incremental-update attacks, generated by the project.
