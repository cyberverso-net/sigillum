# ADR-0014: Generate the test PKI and corpus independently of the code under test

- **Status:** Accepted
- **Date:** 2026-10-23

## Context

Differential and unit tests need certificates, CRLs, OCSP responses and timestamp tokens covering valid, expired, revoked, misconfigured and malformed cases, and signed documents built on them. Real certificates and signed documents cannot be used: they expire, they may contain personal data, and their licences are unknown. If the same code produced the fixtures and consumed them, an encoding defect would be invisible to the tests.

## Decision

A dedicated, unpublished crate, `sigillum-testpki`, generates the test PKI and its artefacts. It uses tools independent of sigillum's own encoders: `rcgen` for certificates and CRLs, and a pinned OpenSSL command-line version for OCSP responses and timestamp tokens. All validity periods are fixed far in the future and all tests use a fixed validation time.

The generated artefacts are committed under `testdata/`, together with a manifest that records, for each artefact, its purpose and the result expected from DSS. Regeneration is an explicit step, not part of every build. Byte-for-byte reproducibility is not required, because ECDSA signatures are randomised; instead, continuous integration checks that every artefact is parsed by OpenSSL and validated by DSS with the result recorded in the manifest.

## Alternatives considered

| Option | Advantages | Disadvantages |
| --- | --- | --- |
| Shell scripts around OpenSSL only | Simple; fully independent | Hard to maintain; weak handling of edge cases such as malformed extensions |
| Generator built on sigillum's own encoders | One code base | Fixtures share the defects of the code under test |
| Rust generator using independent crates and OpenSSL | Maintainable; independent of the code under test; edge cases expressible in code | Two external tools to pin |

## Consequences

The test PKI is the first deliverable of phase 0, because the differential harness has nothing to compare without it. Malformed variants are generated by mutating valid artefacts in the generator, and are recorded in the manifest like any other artefact.
