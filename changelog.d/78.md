### Added

- ADR-0024 sets the rules for decoding untrusted input in the library crates. It requires that every public decoding entry point enforce a documented, caller-configurable input size limit. Each such entry point must also have a fuzz target. Before every decoding of DER from untrusted bytes, including encapsulated values, an allocation-free walk must check the DER lengths. The walk is placed in a public module of `sigillum-pki`. An untrusted object identifier gives INDETERMINATE with "not supported" when it fails any of four checks. They are the canonical syntax, the limit of 2^28 on arcs, parsing, and a round trip. Dotted text is encoded to DER by an encoder of sigillum's own, so `const-oid` parses untrusted identifiers only from DER. Arcs of 2^28 or more are recorded as divergence DIV-2. Threat P2 of the threat model, ADR-0011, the architecture overview and the review checklist refer to the ADR.
