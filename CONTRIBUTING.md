# Contributing to sigillum

Thank you for your interest. This document sets out the rules that keep the project's code legally clean, its behaviour verifiable and its review manageable.

## Before you start

Check [docs/project/scope.md](docs/project/scope.md). Features listed as deferred or excluded are not accepted without a prior discussion in an issue. For anything larger than a small fix, open an issue first so the approach can be agreed before you invest time.

How work is planned and accepted is described in the [development process](docs/development/process.md); the checks every change must pass are in [quality gates](docs/development/quality-gates.md); writing conventions are in the [style guide](docs/development/style-guide.md). Significant decisions are recorded as [architecture decision records](docs/design/adr/README.md).

## The provenance rule

sigillum is an independent implementation of published standards, distributed under Apache-2.0 OR MIT:

- Implement from the specifications: ETSI ENs and TSs, IETF RFCs, ISO 32000 for PDF, and the eIDAS legal texts. Cite the clauses you implement.
- Do not include code or test data from projects whose licence is incompatible with Apache-2.0 OR MIT, including DSS (LGPL-2.1). DSS is used only as an external test oracle, as set out in [ADR-0004](docs/design/adr/0004-dss-as-test-oracle.md).

By signing off your commits (below) you confirm that your contribution complies with this rule.

## Developer Certificate of Origin

All commits must carry a `Signed-off-by` line certifying the [Developer Certificate of Origin 1.1](https://developercertificate.org/):

```
Signed-off-by: Your Name <your.email@example.org>
```

Use `git commit -s` to add it. There is no contributor licence agreement. Contributions are licensed under Apache-2.0 OR MIT, as stated in the [README](README.md).

## Code standards

- Rust edition 2024; minimum supported Rust version as stated in [docs/design/architecture.md](docs/design/architecture.md).
- `cargo fmt` clean; `cargo clippy --all-targets -- -D warnings` clean.
- No `unsafe` outside `sigillum-ffi`.
- No `unwrap`, `expect` or `panic!` on paths reachable from input; return typed errors.
- Public items documented, with a reference to the standard clause they implement where applicable.
- No new dependency without a short justification in the pull request; licences must pass `cargo deny check`.

## Tests

- Every behaviour change comes with tests.
- Signature creation changes must pass the differential tests against DSS (`sigillum-oracle`).
- New parsers come with a fuzz target.
- Test data must be generated by the project's test PKI or carry a recorded licence; never add real signed documents containing personal data.
- Intentional divergences from DSS are recorded in [docs/design/divergences.md](docs/design/divergences.md).

## Documentation and language

Documentation and comments are written in British English, following the [style guide](docs/development/style-guide.md). Keep the documents in `docs/` in step with the code: a change to scope or goals needs an update to the relevant document in the same pull request.

## Commit messages

A short imperative summary line (at most 72 characters), a blank line, then the reason for the change. Reference issues as `Refs #12` or `Closes #12`.
