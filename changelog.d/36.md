### Added

- The `validate-timestamp` mode of `tools/dss-oracle`, which validates a standalone RFC 3161 timestamp token with DSS at a fixed validation time, using only the trust anchors, certificates, CRLs and OCSP responses given on the command line. With `--data`, or `--digest` and `--digest-algorithm`, it also checks the message imprint of the token. It writes the DSS reports as XML, unchanged, and `summary.json` with the indication, the sub-indication and details of the token. An input that DSS cannot parse gives the result `rejected` with the parser message and exit code 0. Before the validation, the mode makes the calls that DSS makes on each input during it, so that an input that DSS cannot parse or use is rejected instead of being dropped silently or failing the run. An input that DSS can use is never rejected. The schema of `summary.json` is described in `tools/dss-oracle/README.md`.

### Changed

- `tools/dss-oracle` depends on `dss-policy-jaxb`, `dss-utils-apache-commons` and `dss-crl-parser-stream` 6.5.1, which DSS needs at run time for its default validation policy, its utilities and its CRL parser.
