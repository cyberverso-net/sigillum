### Added

- `sigillum-oracle`, the unpublished differential test harness. `Validation` describes a run of the `validate-certificate`, `validate-timestamp` or `validate-document` mode of `tools/dss-oracle` with the files that DSS may use, or the run of an artefact of the corpus. `run` returns the parsed `summary.json` as a `Summary`, and `check` compares it with an `Expected` result and reports each member that differs with its JSON pointer, the expected value and the value found. The report lists at most 256 differences in 64 KiB and counts the others. The runs of Java are behind the feature `dss`, off by default, so the crate builds and its tests run on Linux, macOS and Windows without Java or Maven.
- The workflow `differential.yml`, which runs `cargo test -p sigillum-oracle --features dss` on Linux without network for every pull request and every push to `main`. It validates the whole corpus twice and fails on any result other than the expected one, and on any summary that differs between the two runs.
- A fuzz target, `summary`, for the reader of `summary.json` and the comparisons of `sigillum-oracle`.

### Changed

- The format of `testdata/manifest.toml` is now version 2. The optional field `dss-divergence` names, for an artefact on which DSS gives another result than the prediction, the entry of `docs/design/divergences.md` that records it and the result that DSS gives. `sigillum-testpki verify --dss`, `sigillum-oracle` and the tests of `tools/dss-oracle` read the divergences from it, in place of the two lists that `sigillum-testpki` and `ValidateCertificateTest` held. The artefact files are unchanged.
- The fuzz target `manifest` of `sigillum-testpki` also checks that every manifest it parses is written back and read back unchanged.
