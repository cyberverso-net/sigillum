### Added

- `sigillum-testpki verify --openssl`, which checks every artefact of the test corpus with OpenSSL and compares the result with `expected-openssl` in the manifest: certificates with `openssl verify`, private keys with `openssl pkey`, CRLs with `openssl crl -verify` and `openssl verify`, OCSP responses with `openssl ocsp` and timestamp tokens with `openssl ts -verify`, at the validation time of the manifest with `-attime`, and CRLs also by their `thisUpdate` and `nextUpdate`. A missing or unreadable file stops the check of its artefact, and never counts as a rejection. It runs only with the OpenSSL release that the manifest header names, and fails with a message naming both versions otherwise. `--openssl-program` names the program to run, and `--openssl-version` checks another release against the same expected results.
- The workflow `fixtures-openssl.yml`, which builds OpenSSL from its source, checked against a recorded SHA-256 digest, and runs `verify --openssl` without network on every pull request and on every push to `main`: with OpenSSL 3.5.9, the release of the manifest, and with OpenSSL 4.0.3.
- The fuzz target `openssl_output` for the readers of OpenSSL output and manifest notes.

### Changed

- `sigillum-testpki verify` needs a check to run, such as `--openssl`, and no longer reports that it is not implemented.
- The manifest records the results of OpenSSL 3.5.9, a long-term support release, in place of OpenSSL 3.0.13, which is no longer supported. A vanilla build of OpenSSL 3.0.13 verifies `ocsp/signer-under-expired-ca`, which the manifest expects rejected and which OpenSSL 3.5.9 and 4.0.3 reject.
- The manifest notes of every OCSP response with a status say that `openssl ocsp` compares `thisUpdate` and `nextUpdate` with the current time only, so the expected OpenSSL result does not cover freshness. The corpus files are unchanged.
